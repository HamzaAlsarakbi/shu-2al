# Fine-tuning Syrian drama: data and evaluation

Research date: **2026-11-02**. Scope: Damascene Arabic speech recognition output → corrected Arabic and idiomatic English subtitles, Qwen3-8B QLoRA, one shared RTX 3070 with 8 GB, deployment through llama.cpp. Research only: no training, remote access, package installation, or model benchmarking was performed.

**Recommendation:** treat 45.5 → 45.7 chrF++ as an unresolved comparison, not evidence of either improvement or a model ceiling. First establish independent, audio-checked evaluation; then spend annotation effort on errors in existing targets, recurring idioms, and recoverable ASR errors. Add targeted glossary/retrieval support before buying more random parallel data with annotation time. The quantities, mixtures, thresholds, and experiment budgets proposed below are **engineering hypotheses**, unless explicitly attributed to a source.

## 1. What the present result establishes

The supplied experiment history shows a large round-2 improvement over base, followed by little movement with more episodes. It does **not** isolate the cause: round 2 simultaneously changed annotation quality, number of episodes, Arabic intermediate supervision, and auxiliary data. Same-annotator references can reward the annotator's phrasing; replacing overlap metrics alone does not remove that bias. Reference design materially affects metric rankings, as demonstrated by [Freitag et al. (2020)](https://aclanthology.org/2020.emnlp-main.5/).

Reading the implementation reveals several confounds worth controlling before interpreting another run:

| Observation in this checkout | Consequence for the next comparison |
|---|---|
| [ft_llm.py](../../worker/shu2al_worker/ft_llm.py) uses 8-line windows with training stride 4 and evaluation stride 8. | Most episode lines are supervised twice. Approximately 3,671 × 2 episode-line exposures versus 2,000 auxiliary-line exposures means roughly **79:21 episode:general by line exposure**, not 65:35 from unique lines. The batch-count ratio is also about 79:21; neither is the actual Arabic/English loss-token ratio. |
| Each window's loss is averaged over its answer tokens, then gets one optimizer update. | Every window has equal step weight, although longer answers contain more tokens. Record both window sampling and loss-token counts when comparing mixtures. |
| Training context contains reference English; evaluation context contains the model's previous English. | Measure robustness to propagated mistakes. Never give an evaluated system reference English as context. |
| The training loader removes items without English before constructing windows. `windows()` takes a flat list without episode/scene IDs. | Skips can make nonadjacent dialogue appear adjacent; concatenated episode JSON can create windows across episode boundaries. The supplied files were not available to verify whether that occurred. Preserve boundaries and skipped positions in future exports. |
| Missing `fix` defaults to the original ASR. Only 858/3,671 lines have an explicit correction in the supplied round-3 data. | Missing corrections are identity targets, not evidence that the audio was checked and the ASR was correct. Audit that distinction. |
| Only parsed English with a nonempty reference is scored. Arabic quality, uncertainty, timing, and subtitle fit are unscored. | Report Arabic correction and safe handling of unsupported content separately. Preserve unscorable items in a failure/coverage audit. |
| The CLI default is **3 epochs**, although the reported experiments used 1. The training shuffle has no fixed seed. | Record the exact command, seed, data hashes, prompt, and model/adapter revision. Do not accidentally attribute an epoch or ordering change to data quality. |
| [translate.rs](../../crates/server/src/translate.rs) uses JSON, per-cue budgets, verification, and shortening; fine-tuning uses numbered `ar/en` text without duration budgets. | The pipeline comparison changes both the model and its surrounding procedure. Compare models under a common procedure, then compare complete served pipelines. |

These are code observations and arithmetic, not explanations proven by the current scores. In particular, poor performance on a garbled source is not necessarily a translation-model failure.

## 2. Evaluation that measures the desired behavior

### 2.1 Metrics, Arabic evidence, and 8 GB feasibility

Keep **chrF++** for continuity and add **COMET-22** as an affordable semantic cross-check. Calibrate either against blinded human judgments on this show's audio. Use QE to prioritize review, not to certify a target as correct.

The following feasibility estimates assume **exclusive GPU access**, evaluation mode, short cue inputs, and batch size 1 initially. Weight-memory arithmetic is not a measured peak. These models normally use Python evaluation libraries, not llama-server. If “4-bit models only” is a strict rule for evaluators too, use their CPU implementations; ordinary COMET scoring does not require a second large model in GPU memory. Avoid establishing a benchmark with an uncalibrated 4-bit metric.

**The strongest direct dialect evidence has limits.** [Yakhni and Chehab, AbjadNLP 2025, §8/Table 2](https://aclanthology.org/2025.abjadnlp-1.13.pdf) used **150 selected Language Wave sentences**, Aya23-8B outputs, and **three Lebanese/English bilingual annotators**. Besides the COMET/xCOMET coefficients above, BLEU had r=.098 and ρ=.074. This establishes moderate segment-level correlation on one output distribution, not reliability on near-tied systems, subtitle condensation, raw ASR, or Syrian idioms.

For broader Arabic evidence, [AfriMTE's WMT24 analysis](https://aclanthology.org/2024.wmt-1.36.pdf) includes **250 English→Egyptian Arabic** adequacy annotations and **187 Darija→French** annotations. Its pooled, all-language Pearson results are .3674 for COMET-22, .2833 for chrF, .4764 for MetricX-24-Hybrid; pooled QE results are .4337 for MetricX-24-Hybrid-QE and .1685 for CometKiwi. **Those are not Arabic-only correlations**, and chrF is not necessarily this experiment's chrF++. This evidence favors checking transfer, not assuming a universal ranking. I found no defensible single MSA-Arabic→English or Damascene→English coefficient covering all the requested metrics under matching conditions.

A useful 2026 warning comes from [Jon et al., AbjadNLP 2026](https://aclanthology.org/2026.abjadnlp-1.41.pdf): their small human evaluation of **four systems on 100 English→Egyptian items** found xCOMET-XL unsuitable for judging their combined accuracy/dialectness objective. That is the reverse direction and partly a dialect-production problem, so it does not contradict the Lebanese→English result. It reinforces that metric quality is task-specific.

Likewise, [WMT24's main metric ranking](https://aclanthology.org/2024.wmt-1.2/) principally evaluates en→de, en→es, ja→zh. The released MetricX-24-Large card reports an aggregate **.705**, versus **.716** for XXL, combining system soft-pairwise accuracy and segment accuracy over those directions. These are **not Pearson correlations**, and the released v2p6 checkpoints differ slightly from the original submission. [MetricX-25 and GemSpanEval](https://arxiv.org/abs/2510.24707) also exist, but their publication alone is no reason to replace a reproducible, locally affordable evaluator. No demonstrated 8 GB Damascene advantage was verified.

### 2.2 Score the real source, and diagnose the ASR ceiling

For each held-out cue, retain **raw ASR**, **human-verified dialectal Arabic**, English reference(s), duration, source audio interval, and recoverability. Produce these views:

1. **End-to-end:** translate raw ASR; compare with independently audio-checked English. Human raters can listen to the audio. This answers whether the viewer gets the intended dialogue.
2. **MT with clean input:** translate the verified Arabic under otherwise identical conditions. The gap is an empirical estimate of headroom available from improving recognition/correction.
3. **Metric-source sensitivity:** score the same raw-ASR translation using raw versus verified Arabic as COMET/QE's source. Label both. The verified-source score evaluates speech meaning; the raw-source score evaluates faithfulness to what the model actually saw. Do not let each candidate supply its own corrected Arabic to its own evaluator.
4. **Arabic track:** normalized CER/WER plus manual counts of changed-correct words, lost negation, name substitutions, and dialect→MSA conversion. Publish normalization rules; a spelling variant is not the same as a meaning repair.

These are proposed diagnostic views. A text-only metric cannot recover information absent from its input; a large raw/clean-input gap is actionable evidence for ASR work, not a reason to hallucinate harder.

### 2.3 Human and LLM judging

**Human primary check:** randomly order and anonymize A/B subtitles, with ties allowed. Let a Syrian/Damascene speaker listen to short scene clips and assess adequacy, idiom meaning, tone, names, invented content, and reading fit. Judge corrected Arabic separately. Record error spans/categories and major/minor severity rather than only a 1–5 impression. Show approximately 3 preceding and 1–2 following source cues where needed; keep the same context across systems. Have a second bilingual reviewer independently score a 50–100-item subset if available. If only the owner can review, disclose single-rater uncertainty; it still improves on treating frontier annotations as human truth. Comparative evaluation has supporting evidence from [side-by-side human MT evaluation, ACL 2025](https://aclanthology.org/2025.acl-long.1002/).

**Local judge:** an untuned Qwen3.5-9B Q4 already served here can run a separate grading session after translation; use it for disagreement triage. Do not treat the translating adapter as its own arbiter. A dedicated alternative actually exists: [Unbabel/M-Prometheus-3B](https://huggingface.co/Unbabel/M-Prometheus-3B), based on Qwen2.5-3B-Instruct; the card describes 480k multilingual assessment/comparison training instances and a supplied grading template. Its Q4 weights should be roughly 2 GB plus runtime, and 7B Q4 roughly 4–5 GB: estimates, not tested GGUFs. Use an established conversion path before depending on llama.cpp compatibility; preserve its intended prompt and check the model's custom license. Its [2025 paper](https://arxiv.org/abs/2504.04953) validates multilingual judging but does not establish Damascene-drama correlation. A smaller dedicated judge may grade fluency well while still misunderstanding the idiom.

**Frontier judge during development:** use a model from a different family from the Claude annotator, e.g. **Gemini 4 Argon**, whose `gemini-4-argon` release is listed on **2026-10-13** in [Google's release notes](https://ai.google.dev/gemini-api/docs/changelog). **Claude Opus 5.5** also demonstrably exists ([2026-09-22 announcement](https://www.anthropic.com/claude-opus-5-5)), but judging Claude-derived targets with another Claude snapshot is weaker independence. No Damascene judge validation for either current frontier model was located. These are optional offline annotation/audit tools; no paid API belongs in production.

[GEMBA-MQM](https://aclanthology.org/2023.wmt-1.64/) supplies a defensible starting pattern: fixed few-shot demonstrations and error-span/severity annotation. Its GPT-4 findings are evidence for that setup on evaluated language pairs, not a guarantee for a newer model or Syrian ASR. Proposed project rubric:

```text
Inputs: raw ASR, independently verified Arabic where available, source-only
scene context, show name glossary, cue durations, two anonymous English outputs.
For each output identify supported mistranslation, omission, addition, idiom,
name, tone, and subtitle-fit errors. Quote only the relevant error span.
Judge meaning against verified speech, not similarity to one reference.
If raw ASR cannot support a decision, label source_ambiguous; do not guess.
Return errors {category, severity}, A/B/tie, and source_ambiguous as JSON.
```

Use **two passes with A/B order swapped**, fixed rubric/examples, low-temperature decoding, and saved raw judgments. Count ties, order disagreements, and malformed replies; do not coerce them into wins. Validate judge agreement on at least **100–150 owner-reviewed comparisons**, including clean paraphrases, idioms, negation changes, names, and intentionally unrelated fluent outputs. Include both base and tuned systems. Report pairwise agreement and per-category recall, with bootstrap uncertainty; use rank correlation only where the human rubric has an appropriate ordered score. If the judge favors literal translations or misses the known idioms, retain it as a review assistant. Frontier disagreement is not an adjudicated human label. Self-preference and metric-specific blind spots are documented in [EMNLP 2024's error-level metric analysis](https://aclanthology.org/2024.emnlp-main.802/).

### 2.4 Subtitle quality is more than translation similarity

For English interlingual subtitles, Netflix specifies **42 characters per line**, and adult reading speed **up to 20 CPS**; its general duration range is **5/6 second to 7 seconds**. Two lines maximum and syntactically sensible wrapping are useful project targets. Distinguish these from **English templates**, whose adult cap is **17 CPS**. Sources: [English USA guide](https://partnerhelp.netflixstudios.com/hc/en-us/articles/217350977-English-USA-Timed-Text-Style-Guide), [general requirements](https://partnerhelp.netflixstudios.com/hc/en-us/articles/215758617-Timed-Text-Style-Guide-General-Requirements), [template guide](https://partnerhelp.netflixstudios.com/hc/en-us/articles/219375728-Timed-Text-Style-Guide-Subtitle-Templates). These are house-style targets, not proof of a universal perceptual threshold.

Evaluate **rendered SRTs**: proportion over 20 CPS; p95 CPS; proportion over 42 CPL after actual wrapping; >2-line cues; duration violations; overlaps/zero durations; missing/duplicated IDs; broken speaker allocation; and named-entity consistency. Count visible characters including spaces and punctuation, excluding markup and line-break control characters; document this convention. A total of 84 characters does not ensure two legal 42-character lines when word boundaries matter.

The current initial `reading_budget` uses **17 CPS**, clamped to 16–84 characters; the shorten pass triggers on `fits_two_lines`, not on every reading-speed overflow, and clamps its requested budget to **40–84** characters ([translate.rs](../../crates/server/src/translate.rs)). A short cue can therefore be physically two-line compliant and still too fast. Report both the project's 17-CPS budget compliance and the 20-CPS external reference target. Do not declare the adapter better merely because the final renderer hides length problems, or because an overly aggressive shorten pass deletes meaning.

**SubER** is subtitle edit rate: edit operations and shifts account for text, segmentation, and time; **lower is better**. Its [IWSLT 2022 paper](https://aclanthology.org/2022.iwslt-1.1/) reports stronger agreement with human assessment/post-editing effort than text-only baselines in its evaluated conditions. The [official implementation](https://github.com/apptek/SubER) scores SRTs and defaults to case/punctuation normalization. It is CPU work and requires **independent human-timed/segmented English references** to reveal timing improvements; references inheriting current cue timing cannot validate that timing. It remains reference-edit-based, so legitimate subtitle paraphrases can cost edits.

For text-only adapter ablations, fix cue boundaries and timings. For the complete pipeline, additionally score SubER, spot-check segmentation/shot alignment, and time the owner's edits. [Karakanta et al. (2024)](https://aclanthology.org/2024.lrec-main.563/) found different relationships between metrics and editing effort in en→de/it: edit distances reflected technical/temporal work, neural metrics editing speed. There is no verified SubER-human coefficient for Damascene→English. Track **minutes of editing per minute of video**, with playback/research time separated where practical; keystrokes alone are not quality.

## 3. An independent test set and honest confidence

### 3.1 Separate development, representative test, and challenge material

**E2 has already influenced decisions. Call it development data.** Keep its 165-reference score for historical comparison, but do not use another E2 improvement as final confirmation.

Proposed initial collection:

| Partition | Proposed size and selection | Use |
|---|---|---|
| Development | Existing E2 plus a small new diagnostic sample | Prompt choices, QE threshold calibration, mixture selection, judge calibration. |
| Locked in-show test | **600–1,000 scored cues**, selected as contiguous scenes from **4–6 untouched episodes**, aiming for **40–60 scene blocks** | Representative natural-frequency estimate for Al Nadam. More episodes matter as well as more cues. This is a practical starting budget, not a power guarantee. |
| Locked challenge set | **150–200 additional cues** with idioms, names, mixed speakers, negation, repetition loops, and hard ASR | Separate diagnostic score. Do not average its intentionally enriched difficulty into the representative estimate. |
| Later transfer set | **200–300 cues from another Damascene drama**, held out by show | Check that gains are not only names and plot memorization. Coastal Syrian dialogue is a separate transfer condition. |

Annotate source conditions **before looking at which system wins**. Use two axes: ASR **clean / recoverably corrupt / not recoverable from text-context / audio itself unintelligible**, and semantic **literal / idiomatic-cultural / name-dependent / discourse-dependent**. Multi-label overlapping categories; include cue length/duration and speaker overlap. Preserve natural sampling weights for the representative set. Show denominators, major errors, and coverage per stratum; do not interpret a 10-item category as a stable league table.

“Unrecoverable” needs two definitions. A human can often recover a line from audio that the text-only translator cannot infer. That item is valid for end-to-end quality and abstention evaluation but not a fair test of whether a text model knows an idiom. If even the audio reviewer cannot determine the words, there is no defensible unique English reference: score safe handling/coverage, not agreement with an invented sentence.

### 3.2 Reference independence

Best affordable design: a bilingual human writes or verifies **one reference for every representative-test cue**, from the **audio and scene**, before seeing candidate outputs or Claude's English. Add a **second independent reference for 150–200 paraphrase/idiom-heavy cues**, and a random subset of ordinary cues to diagnose reference sensitivity. If possible, the owner and another Syrian speaker independently translate the difficult subset and adjudicate ambiguity. Keep alternate valid senses and subtitle budgets.

If independent human drafting is too costly, ask a **different-vendor frontier model** to draft from independently verified Arabic with source context, then have the owner verify it against audio. Mark these as **model-drafted, human-verified**, with model/date provenance. Another Claude session is not independence from Claude style. A fresh model can introduce different mistakes; disagreement should trigger audio review rather than majority voting. Research on [reference paraphrasing](https://aclanthology.org/2020.emnlp-main.5/) and [reference quality/quantity, HumEval 2024](https://aclanthology.org/2024.humeval-1.1/) supports diversity and quality, but the latter's experiment is English→Czech, not a Syrian cost optimum.

For scoring, retain the original single-reference historical score and introduce a separately named multi-reference score. SacreBLEU chrF supports multiple references; for COMET, compute scores against each available reference and predeclare aggregation, e.g. their per-cue mean. Report per-reference sensitivity too. Do not choose the reference or aggregation after observing which system benefits. More references on the same cue do not create more independent test items.

Dashboard edits are valuable, but **post-edits of system A can favor system A's wording**. For final evaluation, independently re-check a random subset without showing the original English; preserve valid alternatives from another source. Evaluate all held-out cues, including those the user approved unchanged. Selecting only edited failures changes the target distribution.

### 3.3 Leakage controls specific to this repo

Split by **episode/scene before windowing**, deduplication, synthetic expansion, or retrieval indexing. Keep all overlapping 8-line windows and adjacent context from a scene in the same partition. Normalize conservatively for duplicate detection, then also inspect close matches and recurring catchphrases. English/Arabic variants of a test line, its corrected version, and idiom paraphrases made from it must not enter training.

There is an immediate retrieval trap: [editor.rs](../../crates/server/src/editor.rs) already appends the series glossary and **12 recent approved/edited examples**. [db.rs `approved_examples`](../../crates/server/src/db.rs) has no evaluation-split exclusion. If test episodes are edited in the dashboard, their references can become prompting examples for subsequent evaluations. Freeze a training-only snapshot of examples/glossary **before** test annotation, filter by episode/split, and apply the same policy to every system. Log retrieved IDs and glossary revision. Do not let held-out lines enter summaries or previous-English context through export shortcuts.

### 3.4 Paired uncertainty, power, and sample size

There is **no universal “N lines gives ±1 chrF” rule**. Required size depends on paired differences, cue lengths, scene correlation, and desired effect. The current outputs were not supplied, so this report cannot calculate whether +0.2 is significant. Use [paired bootstrap](https://aclanthology.org/W04-3250/) or [SacreBLEU's paired bootstrap/approximate randomization](https://github.com/mjpost/sacrebleu#paired-significance-tests-for-multi-system-evaluation), and distinguish confidence precision from probability of detecting an effect. The importance of power in MT evaluation is discussed by [Graham et al. (2020)](https://aclanthology.org/2020.emnlp-main.6/).

Recommended analysis, specified before the final test:

1. Generate each system once on identical raw-ASR scenes, carrying **its own prior outputs**. Save ID-aligned predictions and error metadata. Bootstrap scores, not repeated stochastic generations. Freeze the inference procedure: HF bitsandbytes NF4 and served GGUF Q4_K_M are different quantization/runtime conditions. Before claiming deployment improvement, compare the same adapter under a verified llama.cpp conversion on a small fixed development sample, then evaluate the complete served prompt/schema/verify/shorten path. Cache outputs so repeated metric calculations do not repeat the expensive generation.
2. **Paired cluster bootstrap**, 10,000 replicates: resample scene blocks within episodes, preserving the same sampled blocks for both systems and all references. Recompute **corpus chrF++** on each concatenated resample; for COMET compute the mean of its per-cue scores. Report the score difference and its percentile 95% interval. If episodes are the intended population, also examine hierarchical episode→scene resampling and per-episode deltas; 4–6 episodes still provide limited episode-level certainty.
3. **Approximate randomization**, 10,000 trials: swap the two systems' output blocks within each scene with probability 1/2, then recompute the corpus-score difference. Use two-sided `p=(1 + trials at least as extreme)/(1 + trials)`. Swapping individual cues ignores dependencies. SacreBLEU's ordinary CLI implements item-level tests; custom scene grouping is needed for this version.
4. For blind human A/B, report win/tie/loss, major-error counts, and a scene-bootstrap interval on net preference or error-rate difference. Do not discard ties and then describe the result as a fraction of all cues.
5. Pick one primary endpoint and a practical minimum gain before testing. For this dashboard, owner preference/editing effort should validate automatic gains. Use development to select a candidate; evaluate the winner once on the locked test. For several simultaneous final comparisons, adjust for multiplicity (e.g. Holm) or call them exploratory. Replicate promising training recipes with another seed; bootstrap confidence does not include training-seed variability.

For an **additive mean metric**, an initial normal approximation is:

```text
95% interval half-width h ≈ 1.96 σd / sqrt(n)
n for 80% power, two-sided α=.05, effect δ ≈ (1.96 + .84)² σd² / δ²
```

Here σd is the SD of **paired score differences**, not scores from each system separately. Example arithmetic, assuming σd=.10 on a 0–1 neural-score scale and independent cues:

| Intended mean gain δ | Approximate n for 80% power |
|---|---:|
| .020 | 196 |
| .010 | 784 |
| .005 | 3,136 |

A 95% interval half-width .01 needs approximately **385** independent cues under the same assumption; that does **not** provide 80% power for a .01 gain. With scene clustering, a rough planning multiplier is `1+(m−1)ρ`; 10-cue blocks and within-block correlation .10 give **1.9×** the independent-cue requirement. These are illustrative calculations, not measured Syrian variance, and the mean-metric formula is **not directly a corpus-chrF power calculation**.

For chrF++, first estimate its scene-bootstrap half-width **H** on a pilot of **n** cues. Rough precision planning uses `n_new ≈ n × (H/h)²`, holding scene composition and cue lengths similar. For example, if a 165-cue pilot actually yielded H=1.5 chrF points, a target h=.5 would suggest ~1,485 cues; **H=1.5 is hypothetical**. For detection power, simulate representative block samples at candidate sizes using pilot paired corpus statistics and prespecified alternatives (e.g. +1 chrF), then estimate the fraction whose interval excludes zero. Increasing bootstrap trials reduces Monte Carlo error; it does not compensate for a tiny or biased test set.

## 5. Quality versus quantity, and a useful mixture

[ALMA, ICLR 2024](https://arxiv.org/html/2309.11674v2) provides relevant but bounded evidence: its second stage used **58k high-quality parallel examples** across ten directions after substantial monolingual adaptation. Higher-quality parallel data beat matched random/filtered data; the covered pairs were English with German, Czech, Icelandic, Chinese, and Russian. It did **not** establish that a few hundred noisy Syrian subtitles suffice, or that monolingual adaptation is cheap: the reported stages used up to **20B/12B monolingual tokens**. The transferable lesson is to audit targets and coverage before adding volume, not to replicate ALMA's pretraining on this GPU.

More recent [UvA-MT WMT24](https://aclanthology.org/2024.wmt-1.11/) showed useful LLM MT performance with **100k cleaned pairs** compared with NMT trained on >22M, while lexical metrics could disagree with COMET. [Marco's WMT25 report](https://aclanthology.org/2025.wmt-1.33/) uses QE filtering and teacher regeneration of rejected targets. Neither establishes an optimal Syrian mixture or eliminates the need to audit the filter. [English-Ukrainian QE filtering research (2025)](https://aclanthology.org/2025.unlp-1.9/) compared metrics with thousands of human-rated pairs and found substantial but imperfect predictive value, illustrating why a threshold needs local calibration.

Proposed priority for the next **fixed annotation-time budget**, e.g. four hours:

1. **Recheck a stratified 200–300 existing training cues**, concentrating on corrected Arabic, implausible meaning jumps, idioms, and duplicate/conflicting targets, plus a random control sample. Listen to audio. Estimate major-target-error rate with a binomial interval. Fix or exclude unsupported guesses and flag “assumed unchanged” Arabic. If the audit finds substantial errors, spend the remaining budget repairing these before adding episodes.
2. **Create 150–300 contextual idiom/name examples** from training-only scenes and verified lexical leads. Cover different inflections, speakers, ASR spellings, literal counterexamples, and meanings. Reserve whole idiom families or new contexts for challenge evaluation. Repeating 20 phrases 15 times is not 300 independent concepts.
3. **Annotate new episodes selectively** for new speakers, settings, narrative register, rare phrases, and realistic recoverable ASR errors. New random easy lines are lower priority while the representative set shows little headroom on easy dialogue. Log annotation minutes and later errors fixed per hour to decide between these investments.

For auxiliary filtering, deduplicate and check language/length/ID alignment first; score **verified clean Arabic→English**, not arbitrary garbled ASR, with small CometKiwi or MetricX-Large-QE. Audit samples from low, middle, and high score bins, including retained/rejected idioms. Set a high-precision **review/reject policy from that audit**, not a borrowed universal .8 score. Low QE on a rare correct idiom can reflect the metric's ignorance. Retain hard examples when human verified; do not filter the entire corpus into easy literal sentences. Use another metric plus humans for final evaluation to reduce selection-on-the-evaluator bias.

**Mixture:** there is no published optimum for 3,671 noisy Damascene-drama lines plus Levanti under this QLoRA setup. Keep the current roughly **80:20 episode/general window exposure** as a baseline; first improve the *selection* of those 2,000 auxiliary pairs. Prefer real-source Syrian, then validated Lebanese/generic Levantine dialogue; exclude Egyptian and badly translated synthetic examples in the first controlled comparison. Record actual eligible counts; do not promise there are 2,000 suitable Syrian real-source pairs until inspected.

Then compare **80:20 versus 95:5**, holding total optimizer steps, length distribution, seed, and base checkpoint fixed. Start with **10–15% of the episode share** devoted to verified idiom/ASR examples, capped to avoid domination by repeated phrase families. These are proposed ratios, not literature findings. Later test 60:40 only if the independent set exposes breadth loss. Count unique cues, window exposures, and Arabic/English answer-token contributions. Extra Arabic-copy supervision can dominate longer answers without teaching difficult English.

Change **one factor at a time** for attribution. If learning rate, warmup, accumulation, or epochs change during a data ablation, it becomes a recipe comparison. Matching only “one epoch” is insufficient when dataset sizes and overlap change. For later recipe checks, use a small development-only sweep and saved checkpoints; do not tune against the locked test. Keeping a fixed general-dialect replay share is a plausible guard against narrow adaptation; [Stap et al.'s fine-tuning paradox study](https://www.amazon.science/publications/the-fine-tuning-paradox-boosting-translation-quality-without-sacrificing-llm-abilities) supports retention concerns and mixed-data mitigation, but does not prescribe this project's ratios.

## 6. Turning dashboard corrections into supervision

The database already preserves machine origins (`cues.ar_asr`, `en_mt`), current values (`ar_text`, `en_text`), uncertainty/status, and field-level `cue_edits` history ([schema and edit code](../../crates/server/src/db.rs)). An edit event is **not** automatically a complete, verified training pair. Export the **final verified cue state**, retaining the event history for provenance. Multiple keystroke saves or changes later undone should become one final example, not many contradictory targets. A timing-only edit creates no translation preference; an unchanged line is positive only when explicitly verified.

Recommended future record, extending export metadata rather than assuming these fields already exist:

```text
episode/scene/cue IDs, split, raw ASR, audio interval and audio hash,
final verified Arabic, final verified English, recoverability, error category,
generator model/adapter/prompt/glossary/retrieval revisions, original output,
review status and timestamp, duration/budget, source provenance/license.
```

Keep the exact prompt/context used to obtain a candidate if learning preferences from it. The schema currently does not preserve all of those generation details. Join `cue_edits` to cues and episode metadata; do not train isolated old/new string fragments as if each were a complete answer.

| Method | Training signal | Fit for the present data/hardware |
|---|---|---|
| **SFT on final corrections** | Same raw-ASR/scene prompt, chosen corrected Arabic + English only. | **First choice.** Reuses the proven ~7.2 GB answer-only training path. Include verified unchanged examples and the general replay share. Distinguish semantic repairs, style-only edits, and uncertainty handling. |
| **DPO** | Same prompt with verified edit as chosen and actual model answer as rejected; optimizes relative preference against a frozen reference policy. [Original paper](https://arxiv.org/abs/2305.18290). | Useful once authentic, prompt-matched pairs exist. A second full reference model plus concatenated chosen/rejected batches is a poor fit at 7.2 GB. Precompute reference log probabilities sequentially; share a frozen quantized base with separate frozen/trainable adapters where supported; forward chosen/rejected separately. This still needs a new memory-tested training path. |
| **CPO** | Reference-model-free contrastive preference loss **plus chosen-output likelihood anchoring**. [ALMA-R paper](https://arxiv.org/abs/2401.08417). | Most relevant MT-specific preference evidence: **22k parallel sentences**, LoRA-scale trainable parameters, non-Arabic WMT evaluation. Removes reference-model residency, but still processes two responses and is not a drop-in for current `answer_loss`. |
| **KTO** | Desirable/undesirable prompt-output labels; no paired winner/loser required. [Paper](https://arxiv.org/abs/2402.01306). | Fits explicit approve/reject feedback without a rewritten target. Edits already provide stronger paired/target information, so KTO is lower priority. Reference-policy/KL work and class balancing remain; “no pairs” does not mean “no compute.” |

**How many?** No validated minimum exists for Damascene subtitles. ALMA-R's 22k is a successful experimental scale, not a threshold. For this project, use **200–500 distinct, verified corrections** as an SFT pilot; consider preference learning at **500–1,000 genuine prompt-matched pairs across several episodes**, then construct a **250/500/1,000-pair learning curve** if collection permits. These are planning budgets, not promises. If only 50 trustworthy pairs exist, glossary/retrieval and a small SFT pilot are more defensible than a heavily tuned DPO claim.

Do not label “shorter” or “different wording” as globally preferable without the cue's duration and source meaning. A corrected Arabic source must not be given only to the chosen response while the rejected response was generated from raw ASR; both completions must correspond to the **same conditioning prompt**. For eight-cue outputs, either reconstruct the whole prompt/answer pair and keep unaffected lines identical, or train a documented cue-level format consistently. Do not pair a one-line edit against an eight-line rejected answer.

Guard against drift: train offline in small, versioned batches; keep the previous adapter; retain representative verified ordinary lines and a little general dialect replay; separate style-only from semantic preferences; inspect response length, Arabic over-correction, refusal/uncertainty rate, hallucinations, and held-out literal accuracy. A replay mix and conservative short runs are proposed safeguards. [WMT24's empirical analysis of preference alignment](https://aclanthology.org/2024.wmt-1.127/) shows that alignment benefits depend on candidate/data/objective choices; it is not automatically superior to SFT. Do not continually train on the model's own unreviewed outputs or on its judge's preferences alone.

## 7. Garbled ASR and the Arabic intermediate

Corrected Arabic is an **explicit supervised intermediate with product value**, not free-form hidden reasoning. Autoregressive English tokens can attend to previously emitted Arabic. That offers a plausible learning benefit, but the model can still output mutually consistent invented Arabic and English.

Relevant literature:

- [Dou et al., Speech Translation Refinement (2025)](https://arxiv.org/abs/2501.15090) jointly refines ASR and translation; it reports benefits over translation-only refinement on MuST-C/CoVoST2 with context and parameter-efficient tuning. This supports the idea, but those systems also receive an initial translation; it is **not a causal proof** for this raw-Syrian-ASR→`ar/en` recipe.
- [Li et al., Interspeech 2024](https://www.isca-archive.org/interspeech_2024/li24h_interspeech.pdf) reports Arabic ASR post-correction can regress: Whisper-v2 **CER 5.33→6.79**, while Whisper-v3 **5.57→5.35** improved slightly. The earlier project's warning is justified; applying a corrector universally can corrupt good recognition.
- [HyPoradise](https://arxiv.org/abs/2309.15701) demonstrates generative correction from **N-best hypotheses** across speech domains. This establishes a method worth testing, not Syrian accuracy. [Naderi et al., Interspeech 2024](https://publications.idiap.ch/attachments/papers/2024/Naderi_INTERSPEECH_2024.pdf) studies confidence-gated correction to limit damage to correct transcripts.

The experiment needed here is a **matched-data ablation**: identical verified cues, mixture, context, seed, and optimizer-step budget; compare raw→English, raw→Arabic+English, and, on a diagnostic subset, verified-Arabic→English. Evaluate both English quality and false Arabic repairs; record total output tokens and wall time. Round 1 versus round 2 cannot answer this because several interventions changed together. An intermediate that improves English but makes the requested Arabic track less faithful is not an unqualified success.

For alternatives:

| Approach | What it resolves | Cost/limitation here |
|---|---|---|
| **Joint corrected-Arabic then English** | Shares context, directly supervises the requested two tracks. | Keep as baseline; more output tokens and errors can propagate from the intermediate. No extra resident model. |
| **Separate correction then translation** | Makes repairs independently inspectable/cacheable; can send unchanged clean text through. | Two sequential calls/models, extra prefill/startup; can use the same local model in two roles. Compare translation-only from the corrected result with raw+corrected dual input to expose unsupported repairs. A specialized corrector needs real raw/corrected pairs. |
| **2–4 diverse ASR hypotheses for flagged spans** | Exposes acoustic alternatives the translator cannot reconstruct from top-1 text. | Current [asr.py](../../worker/shu2al_worker/asr.py) saves only top-1 text and no token probabilities. Requires an explicit decoder/export change and extra ASR compute. Start on flagged spans, not every cue. Measure whether the correct words appear in any hypothesis before training on them. |
| **Lattice/confusion network** | Can preserve alternatives more compactly than full N-best strings. | Current text prompt has no structured lattice interface. Linearizing alternatives needs training/examples and may confuse a 9B model. This is not a cheap near-term change. |
| **Confidence-guided repair** | Restricts correction/re-ASR/review to uncertain words or spans. | Current [align.py](../../worker/shu2al_worker/align.py) emits a CTC alignment `score`; **that is not calibrated probability that an ASR word is correct**. The aligner is fitting the supplied text and can confidently align a wrong word. Calibrate against owner-labeled errors; combine with repetitions, density, failed alignment, and ASR disagreement. |

Passing strings such as `[low confidence: ...]` or quantized confidence bins is a plausible interface, but no direct evidence was verified that numeric per-word scores improve Damascene translation with Qwen. Use gating for review first; later test confidence-aware prompts/training against the same cues. A raw generative token probability, an alignment score, and lexical correctness are different quantities.

For irrecoverable text, adopt an explicit **uncertain/review policy**. Keep uncertain source wording, avoid invented specific names/actions, and request audio review or targeted re-ASR. The production JSON already has `uncertain`; the fine-tune output does not. A future export can include that status alongside `ar/en` with an explicit parser/schema change. Do not silently overload empty English to mean both noise and unintelligible speech. Empty noise targets require labeled nonspeech examples; genuinely unintelligible speech requires an explicit convention.

Do not supervise an eloquent English reconstruction when neither input nor context supports it. Remove such items from positive translation loss, but **keep their positions, audio, and uncertainty labels** so the system learns when to abstain and evaluation still measures coverage. On recoverable errors, supervise the exact dialectal correction and its meaning. Synthetic ASR corruption can augment these only after matching real confusion patterns and verifying that the resulting input still contains recoverable evidence. Evaluate natural corruptions separately.

## 8. Glossary and retrieval versus another adapter

This repo already supports both a `glossary` table and examples appended by [learning_context](../../crates/server/src/editor.rs). The present examples are recent approved lines rather than query-selected near matches. The smallest useful change is therefore **selection and provenance**, not a new vector database.

[Li et al., KnowledgeNLP 2025](https://aclanthology.org/2025.knowledgenlp-1.7/) found retrieved demonstrations more useful than terminology and retrieval better than generation in its specialist-domain experiments. Those domains are not Damascene drama, so this is evidence for a cheap controlled trial, not a guaranteed gain. Newer [WMT26 terminology work](https://aclanthology.org/2026.wmt-main.40/) studies retrieval and preference tuning together, but does not establish a Syrian optimum.

Proposed implementation-independent policy:

- **Names:** maintain per-show Arabic aliases, canonical Arabic/English spelling, nicknames, roles, and relationships. Inject the short relevant list. A canonical spelling can be required; identifying whether a garbled word really denotes that character is still a semantic decision.
- **Idioms:** store the surface forms, contextual sense and tone, natural short English alternatives, literal counterexample, and owner verification/source. Retrieve a few relevant records, with “use only for this sense” guidance; do not make all idioms unconditional hard translations.
- **Past lines:** retrieve **2–4** verified examples from training-only scenes using lexical/character n-gram similarity first, with conservative Arabic normalization and phrase aliases. Retain original spelling/negation for the prompt. For the present few thousand lines, CPU ranking suffices; embeddings can be a later alternative if lexical retrieval demonstrably misses useful matches.
- **Prompt budget:** replace low-relevance members of the current 12-example block; initially cap examples around **300–600 tokens**. Log IDs/scores, actual prompt tokens, cache behavior, and latency. Dynamic examples may reduce llama.cpp prefix-cache reuse. Do not blindly append hundreds of terms to the ~1k-token show brief.
- **Controls:** compare no examples, current recent examples, and retrieved examples with the **same model, same glossary, same input, and comparable prompt-token budget**. Then test the best retrieval policy on both base and tuned systems. The comparison needs a training-only retrieval snapshot and holdout exclusions from §3.

Glossary/retrieval is best for **names, rare expressions, repeat dialogue, immediate reversible fixes**. SFT is best for a **recurrent behavior across diverse inputs**: conservative repair, idiomatic condensation, and the dual-track format. Preference learning may refine consistent edit preferences after SFT. They can coexist; retrieval cannot supply missing acoustic evidence, and a memorized idiom example is not evidence of general comprehension. Include known phrases in new contexts and entirely unseen idiom families in separate challenge slices.

## Recommended next experiments

Ranked by expected value for this project. Costs are **estimates** based on the supplied ~7.2 GB training peak and ~18 minutes/434 HF-generated input lines; exact job times and new sequence peaks remain unmeasured. Schedule GPU jobs sequentially through the existing queue and release the model between training, generation, and metric scoring. No experiment below was run for this report.

1. **Establish an independent comparison and the ASR ceiling.** **Exact change:** retain E2 as development; freeze 600–1,000 representative cues from 4–6 untouched episodes plus 150–200 challenge cues, independently verify Arabic/English from audio, and add a second reference for 150–200 ambiguous/idiomatic items. Compare saved round-2/round-3 adapters under identical raw-ASR prompts and a 150-cue verified-Arabic-input diagnostic. Use chrF++, COMET-22, scene-bootstrap deltas, blind owner A/B, Arabic errors, and CPS. **Expected effect:** trustworthy decisions; identifies whether the plateau is real and how much better ASR could help, without promising a score increase. **3070 cost:** no training; ~31–50 minutes per system for 750–1,200 total translated lines if the supplied HF rate transfers, plus metric scoring with a separate small model or CPU; annotation is the main cost. **Success:** stable independent rankings or an honest inconclusive interval, and a measured raw/clean-input gap. Never “pass” +0.2 just because the point estimate rose.

2. **Test relevant memory before more training.** **Exact change:** freeze the current model; add 30–50 owner-verified idiom-sense/name entries, and replace the 12 recent-example policy with 2–4 retrieved training-only examples capped at 300–600 tokens. A/B against the current memory policy at comparable context size, first on development then on the locked set. **Expected effect:** better recurring idioms and canonical names, minimal collection cost, possible little change on unrelated cues. **3070 cost:** no training, same Q4 resident model, CPU retrieval, modest extra/changed prefill and KV use; one extra generation per evaluation arm. **Success:** fewer independently judged idiom/name errors with no increase in unsupported repairs, ordinary-line errors, or >20-CPS cues; acceptable measured latency. Require held-out contexts, not exact retrieved test lines.

3. **Spend one annotation budget on repairs and coverage, then run matched SFT.** **Exact change:** audio-audit 200–300 existing training cues; fix/remove unsupported targets; add 150–300 verified idiom/recoverable-ASR examples.
